# Building From Source

> [!info] Pipeline
> The schematic, placement and most of the routing are generated by the Python scripts in `tools/`, and so are the plate, the case, the manufacturing files and the pictures. Every step from layout to Gerbers can be rerun. All paths are in the repo, [milindmadhukar/keygen](https://github.com/milindmadhukar/keygen).

## Requirements

- [KiCad 10](https://www.kicad.org), including its `pcbnew` Python module and `kicad-cli`
- Python 3 with `numpy` and `pycairo`
- The [GitHub CLI](https://cli.github.com), logged in, to publish the generated files (below)
- Java 17 or newer and [Freerouting 2.5.0](https://github.com/freerouting/freerouting/releases),
  saved as `tools/freerouting-2.5.0.jar` (not checked in)
- For the case: [build123d](https://build123d.readthedocs.io/) and
  [shapely](https://shapely.readthedocs.io/) in a virtual environment that can also see KiCad's
  `pcbnew`:

  ```sh
  uv venv ~/.venvs/keygen-cad --python /usr/bin/python3 --system-site-packages
  uv pip install --python ~/.venvs/keygen-cad/bin/python build123d shapely
  ```
- For the keycap models: an [OpenSCAD development snapshot](https://openscad.org/downloads.html#snapshots)
  (2025 or later; the 2021.01 release cannot run KeyV2), as `openscad` or `$KEYGEN_OPENSCAD`
- For the Blender scene: [Blender](https://www.blender.org) 5.2, as `blender` or `$KEYGEN_BLENDER`

```sh
git clone --recursive https://github.com/milindmadhukar/keygen.git
```

## Schematic

The schematics are generated, so edit the tables in
`tools/gen_schematic.py` rather than the KiCad files:

```sh
python3 tools/gen_schematic.py     # write pcb/*.kicad_sch
python3 tools/check_schematic.py   # KiCad ERC plus a netlist check against the tables
```

## PCB pipeline

Run these in order. Each step is a script in `tools/`.

| Step | Script | What it does |
|---|---|---|
| 1 | `gen_pcb.py` | Places every footprint from the schematic, draws the outline, picks mounting holes |
| 2 | `trim_outline.py` | Runs the bottom edge along the bottom row and the thumb keys (on a routed board, reroute whatever it cuts) |
| 3 | `route_pcb.py` | Routes signals with Freerouting, leaving ground to the fill |
| 4 | `finish_route.py` | Grid maze router for whatever Freerouting leaves (`--include-gnd`, `--pads-to-ground REF.PAD`) |
| 5 | `smooth_route.py` | Straightens tracks into 0/45/90° runs |
| 6 | `stitch_gnd.py`, `cleanup_pcb.py` | Ground stitching vias; removes dangling copper |
| 7 | `sync_pcb.py` | Relinks footprints to the schematic; redraws any `keygen` library footprint whose graphics changed in the library |
| 8 | `silkscreen_art.py` | Moves footprint labels off the edge, pads and other silkscreen, then the black-mask stackup and the silkscreen artwork; rerunnable, replaces its previous output (about 2 minutes) |

Then check the result. `kicad-cli pcb drc --schematic-parity` is the judge; pass it an absolute path.

```sh
kicad-cli pcb drc --schematic-parity --units mm "$PWD/pcb/keygen.kicad_pcb"
python3 tools/check_datasheets.py      # exits 1 on any FAIL; -v lists the passes
```

## Regenerating everything else

Everything below the PCB is regenerated by one script, which knows what each generator reads and
writes and reruns only what is stale:

```sh
python3 tools/regen.py            # run the stale steps, in order
python3 tools/regen.py --blender  # the same, with the Blender parts file and studio renders
python3 tools/regen.py --check    # list the stale steps; exit 1 if any
python3 tools/regen.py --force    # rerun every step (or name steps: --force case keymap)
```

A step's inputs are its script, the `tools/` modules it imports and its data files (the PCB, the
keymap, `bom/bom.csv` and so on). Their hashes from the last run are in `tools/regen.lock`,
committed with the change, so the repo records that every output, published or not, is current. A full run takes about 30 minutes: 17 for the Blender renders, 7 for
the KiCad renders and 2 for the case.

- **Claude Code** runs it at the end of every turn (the Stop hook in `.claude/settings.json`), and
  a failing step comes back as feedback to fix.
- **Git** refuses a commit while anything is stale (`.githooks/pre-commit`; turn the hooks on with
  `git config core.hooksPath .githooks`).

One run at a time: a run started while another holds the lock waits for it, and the Stop hook skips
instead, so two sessions never render the same files at once.

The plate and case follow the PCB through the shared geometry in `tools/case_geometry.py`. The
steps and what they run:

```sh
python3 tools/gen_keycaps.py                        # keycaps: pcb/lib/keygen.3dshapes/Keycap_*: DSA 1u and 1.25u from KeyV2
python3 tools/gen_schematic.py                      # schematic: pcb/*.kicad_sch, pcb/lib/
python3 tools/gen_plate.py                          # plate: pcb/plate/, case/plate/{gerber,dxf}/, case/plate/PLATE.md
~/.venvs/keygen-cad/bin/python tools/gen_case.py    # case: case/{bottom,top}/, case/plate/{stl,step}/, case/foam/, the fit check
~/.venvs/keygen-cad/bin/python tools/check_mechanical.py  # pairwise and tolerance clearances, plus the 3D fit check
python3 tools/render_case.py                        # case-renders: assets/render-case*.png, assets/render-plate.png
~/.venvs/keygen-cad/bin/python tools/gen_models.py  # models: pcb/lib/keygen.3dshapes/: the knob and OLED 3D models
```

and the outputs:

```sh
python3 tools/export_fab.py      # fab/: Gerbers, drill files, ORDER.md
python3 tools/export_bom.py      # fab/: assembly BOMs from the schematic
python3 tools/render_bom.py      # plan/bom.html and notes/13 from bom/bom.csv
python3 tools/plate_print.py     # case/plate/pdf/keygen-plate-print.pdf
kicad-cli sch export pdf -o pcb/keygen-schematic.pdf pcb/keygen.kicad_sch
python3 tools/render_board.py    # assets/render-{hero,top,bottom}.png, and render-bare*.png without parts
python3 tools/render_routing.py  # assets/pcb-routing.png
python3 tools/render_assembly.py # assets/assembly-*.png: part references on each side, per half
python3 tools/render_keymap.py   # assets/keymap-*.svg: one picture per keymap layer
python3 tools/render_oled.py     # assets/oled-{left,right}.svg: each half's OLED status screen
python3 tools/gen_zmk_layout.py  # firmware/boards/shields/keygen/keygen-layouts.dtsi
python3 tools/gen_blend.py       # blender/keygen-parts.blend (local, see below)
python3 tools/render_blender.py  # assets/render-studio-*: the Blender stills and GIFs
```

## Blender scene

`blender/` holds a realistic model of the finished keyboard: smoke translucent DSA caps lit by the
per-key LEDs, the clear-top lavender switches, the black PETG case, the clear polycarbonate plate and the
black-mask PCB.

- `blender/keygen-parts.blend` holds every part with its material in one collection, `Keygen`.
  `tools/gen_blend.py` builds it:
  - the board and its parts come from KiCad as GLB;
  - the case, the plate and the caps come from their STLs;
  - the LEDs are placed from the PCB;
  - each OLED shows its status screen from `assets/oled-*.svg`, lit pixel by pixel.

  It is gitignored. `regen.py --blender` rebuilds it when the board, the case or the caps have
  changed: the `blender` step is a *local* step, with its hash in the ignored
  `tools/regen.local.lock`, and runs only on request, like `studio-renders`; a plain run, the hooks
  and `--check` skip both, so commits never wait on them.
- `blender/keygen.blend` is the studio file: camera, lights, floor, Cycles and a bloom compositor.
  It **links** the `Keygen` collection, so it always shows the current design, and is edited by
  hand. Open it and press F12 for a Cycles render; the viewport shows an EEVEE preview. After a
  rebuild, reopen the file, or reload the library from the Outliner's Blender File view.
  `python3 tools/gen_blend.py --reset-studio` writes it afresh.
- The LED colours are `LED_SCHEME` in `tools/blend_scene.py` (`gradient`, `lavender`, `white`,
  `rainbow`), and the materials are defined there too.
- `tools/render_blender.py` (the `studio-renders` step) renders the README's pictures from the
  studio file with Cycles: `assets/render-studio-{hero,top,thumbs,oled,side,bottom}.jpg` at 1920 × 1080,
  and the `render-studio-{leds,turntable}.gif` loops. The bottom view turns the
  keyboard over onto the floor, its LEDs off. The hero uses the studio camera, so moving it moves the
  README picture; the other views are set up in `tools/blend_render.py`. `--preview` renders them
  small and noisy into `/tmp/keygen-preview/`.

## Generated files

Everything below is written by a script in `tools/` from the schematic tables and the
PCB. The binaries among them (renders, Gerber zips, case, plate and foam files, the schematic PDF,
the generated 3D models) are not in git. When `main` is pushed, `.githooks/pre-push` refuses the
push while anything is stale, then runs `tools/publish.py`, which uploads whatever changed to two
releases whose tags never move, so their links stay put:

- [`media`](https://github.com/milindmadhukar/keygen/releases/tag/media): the renders and GIFs the README and these notes show;
- [`build`](https://github.com/milindmadhukar/keygen/releases/tag/build): everything to order, print or cut, and the schematic PDF.

The part datasheets are a third release, [`datasheets`](https://github.com/milindmadhukar/keygen/releases/tag/datasheets).
`python3 tools/publish.py --fetch` downloads `media` and `datasheets` into place; `build` comes
from `tools/regen.py`. A fresh clone runs every step on its first `regen.py`.

| File | What it is | Made by |
|---|---|---|
| `fab/keygen-left-gerbers.zip`, `fab/keygen-right-gerbers.zip` | PCB Gerbers and drill files, one order per half (`fab/keygen-gerbers.zip` has both) | `export_fab.py` |
| `fab/ORDER.md` | Order-form settings for the PCBs | `export_fab.py` |
| `fab/BOM.md`, `fab/BOM-*.csv` | Assembly BOMs per half | `export_bom.py` |
| `pcb/plate/keygen-plate.kicad_pcb` | The switch plate as a KiCad board, both halves | `gen_plate.py` |
| `case/` | Everything outside the PCB, one folder per part and one folder per file type inside it (below) | `gen_case.py`, `gen_plate.py`, `plate_print.py` |
| `pcb/keygen-schematic.pdf` | Printable schematic | `kicad-cli sch export pdf` |
| `pcb/lib/keygen.3dshapes/` | 3D models for KiCad's 3D view: knob, OLED module, DSA keycaps (also as STL, for Blender), controller | `gen_models.py`, `gen_keycaps.py`, `gen_schematic.py` |
| `assets/render-*.png` | The board (assembled and bare), case and plate renders | `render_board.py`, `render_case.py` |
| `assets/render-studio-*` | The Blender stills and GIFs | `render_blender.py`, `blend_render.py` |
| `assets/pcb-routing.png` | Both copper layers | `render_routing.py` |
| `assets/assembly-*.png` | Assembly maps: every part's reference on each side of each half, and the power parts enlarged | `render_assembly.py` |
| `assets/keymap-*.svg` | One picture per keymap layer | `render_keymap.py` |
| `assets/oled-*.svg` | Each half's OLED status screen, from ZMK's layout and LVGL's fonts (in the ZMK workspace `firmware/build.sh` fetches) | `render_oled.py` |
| `firmware/boards/shields/keygen/keygen-layouts.dtsi` | ZMK matrix transform and physical layout | `gen_zmk_layout.py` |
| `tools/regen.lock` | The input hashes each step last ran with | `regen.py` |
| `blender/keygen-parts.blend` | The Blender parts and materials (gitignored) | `gen_blend.py`, `blend_scene.py` |

The `case/` folder, after `tools/regen.py` has run (only `PLATE.md` is in git):

```
case/
├── keygen-case.step                    every part in place, for CAD
├── bottom/  stl/  step/                bottom shells (print the STL)
├── top/     stl/  step/                top frames (print the STL)
├── plate/   gerber/  dxf/  stl/  step/  pdf/  switch plates: Gerbers to order, CNC/laser cut files, meshes, solids, 1:1 paper print
│   └── PLATE.md                        plate order-form settings
└── foam/    dxf/  svg/  step/          plate and case foam: 1:1 cut files, solids; switch pads and
                                        gasket strips: solids
```

Every file is named `keygen-{left,right}-<part>` (the foam `keygen-{left,right}-{plate,case}-foam`,
the pads and strips `keygen-{left,right}-{switch-pads,lower-gaskets,upper-gaskets}`, the plate
Gerbers `keygen-plate-{left,right}-gerbers.zip`).
